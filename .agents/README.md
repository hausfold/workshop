# `.agents/` — the harness-neutral layer

Every coding agent invents its own dotfile. This directory is the answer to
that: **the content lives here (or in `AGENTS.md`), and each client's own
directory holds nothing but wiring** — a pointer, a symlink, or a hook
registration. Switch harness, keep the flows.

## The rule

> **One body, many pointers.** A rule, a flow, or a script is written *once*.
> If a file under `.claude/`, `.codex/`, `.opencode/` or `.github/` contains a
> project rule rather than a reference to one, it's a bug — the next agent on a
> different client will run without it.

Corollary: never "fix" a stale pointer by copying the current text into it.

## The four kinds of agent config

Every harness has the same four slots under different names. Knowing which slot
a thing belongs in is most of the work:

| # | Kind | What it is | Ours |
|---|---|---|---|
| 1 | **Instructions** | Always-on context, loaded before the first token. Cheap to read, expensive to bloat. | [`AGENTS.md`](../AGENTS.md) |
| 2 | **Flows** (skills / slash commands / prompts) | On-demand context: a multi-step procedure loaded only when invoked. | [`.agents/skills/<name>/SKILL.md`](./skills) |
| 3 | **Hooks** | Code the *harness* runs, not the model — lifecycle events (session start, pre/post tool use). Deterministic, no tokens. | [`.agents/setup.sh`](./setup.sh) |
| 4 | **Environment** | What the container has before an agent wakes up: packages, network policy, secrets. Usually owned by a cloud UI, not the repo. | `.codex/environments/environment.toml`, the Claude Code web environment |

Rules of thumb: if the model must *decide* to do it, it's 1 or 2; if it must
happen every time regardless, it's 3 or 4. If it's long and only sometimes
relevant, it's 2, not 1 — that's the whole point of skills.

## What lives where

| Path | Read by | Kind | What it actually is |
|---|---|---|---|
| `AGENTS.md` | Codex, OpenCode, Cursor, Zed, Jules, Amp, Copilot-in-editor, and anything else that speaks [agents.md](https://agents.md) | 1 | **The source of truth.** Every project rule. |
| `CLAUDE.md` | Claude Code (CLI, desktop, web) | 1 | `@AGENTS.md` import + a table of Claude-only wiring. Claude Code reads only `CLAUDE.md`, so the import is how it gets the real file. |
| `GEMINI.md` | Gemini CLI | 1 | Symlink → `AGENTS.md`. |
| `.github/copilot-instructions.md` | GitHub Copilot coding agent + code review | 1 | A **real file**, not a symlink: Copilot reads through the GitHub API, where a symlink is just a path string. Short pointer + the five facts a drive-by reviewer needs. |
| `.agents/skills/<name>/SKILL.md` | Codex (scans project `.agents/skills/`), and every other client via the links below | 2 | The flow bodies: `ship`, `docs-sync`, `release`, `earshot`. YAML frontmatter (`name`, `description`) + the procedure. |
| `.claude/skills/<name>/SKILL.md` | Claude Code | 2 | Symlink → `.agents/skills/<name>/SKILL.md`. |
| `.opencode/skills/<name>` | OpenCode | 2 | Symlink → `.agents/skills/<name>`. |
| `.opencode/commands/<name>.md` | OpenCode | 2 | Four-line command that says "read the shared body and follow it" — guarantees `/ship`, `/docs-sync`, `/release` and `/earshot` exist even if skill discovery doesn't fire. |
| `.agents/setup.sh` | all of them, via the hooks below | 3 | Installs Determinate Nix in a bare cloud container, persists `PATH` + `NIX_SSL_CERT_FILE`. No-ops on macOS and where Nix already exists. |
| `.claude/settings.json` | Claude Code | 3 | `SessionStart` → `.agents/setup.sh`. |
| `.codex/hooks.json` + `.codex/config.toml` | Codex CLI | 3 | `SessionStart` → `.agents/setup.sh`, plus the flag that enables hooks. |
| `.opencode/plugins/nix-bootstrap.js` | OpenCode | 3 | Plugin load *is* session start; runs the same script, swallowing every error. |
| `.codex/environments/environment.toml` | Codex cloud | 4 | **Autogenerated — don't hand-edit.** Set its setup script to `bash .agents/setup.sh` in the Codex web UI. |
| `opencode.json` | OpenCode | 1 | Names `AGENTS.md` explicitly. Belt and braces — OpenCode finds it anyway. |

## The harness matrix

| Client | Surface | Instructions | `/ship`, `/docs-sync`, `/release` | Session hook |
|---|---|---|---|---|
| **Claude Code** | TUI + desktop | `CLAUDE.md` → `@AGENTS.md` | `.claude/skills/*` (symlinks) | `.claude/settings.json` |
| **Claude Code on the web** | GUI / cloud | same | same | same — the hook is what installs Nix |
| **Codex** | TUI | `AGENTS.md` natively | `.agents/skills/*` natively | `.codex/hooks.json` |
| **Codex cloud** | GUI / cloud | same | same | environment setup script (UI) |
| **OpenCode** | TUI | `AGENTS.md` natively (+ `opencode.json`) | `.opencode/commands/*` and `.opencode/skills/*` | `.opencode/plugins/nix-bootstrap.js` |
| **Copilot** | GitHub / editor | `.github/copilot-instructions.md` → `AGENTS.md` | — | — |
| **Gemini CLI** | TUI | `GEMINI.md` (symlink) | — | — |
| **Cursor · Zed · Windsurf · Amp · Jules** | GUI | `AGENTS.md` natively | — | — |

Anything not in the table: it either reads `AGENTS.md` (most do now) or it
doesn't, in which case point it at `AGENTS.md` with the thinnest file its format
allows, and add a row.

## Adding a harness

1. **Instructions** — point its file at `AGENTS.md`. Symlink if it reads from
   disk; a real pointer file if it reads through an API (see Copilot). Never
   copy.
2. **Flows** — symlink its skills/commands directory at `.agents/skills/`, or
   drop a four-line command that reads the shared body.
3. **Hooks** — register `.agents/setup.sh`. Don't write a second bootstrap; if
   the new harness needs something extra, add it to that script behind a guard.
4. Add a row to both tables above. A harness that works but is undocumented is
   the same failure mode as a stale copy.

## Known caveats

- **Codex repo-local hooks** have historically not fired in every interactive
  session ([openai/codex#17532](https://github.com/openai/codex/issues/17532)),
  and some builds want an absolute path for `hooks`. If `/hooks` doesn't list
  ours, point your own `~/.codex/config.toml` at this repo's `.codex/hooks.json`.
- **`.codex/environments/environment.toml` is generated by the Codex cloud UI.**
  Editing it here doesn't configure anything; set the setup script in the UI.
- **The OpenCode plugin is best-effort** and deliberately silent: it runs the
  bootstrap on plugin load and swallows failures. A bootstrap that breaks the
  client would be worse than none.
- **Whatever the harness, the fallback is the same:** `./.agents/setup.sh` is
  idempotent and safe to run by hand. If a flake command says Nix is missing,
  that's the fix.

## The rest of the family

Every repo carries this layer: `haus`, `nebelung`, `pounce`, `perch`, `holt`,
`trill`, `hausfold.co`, `org-profile` (the `hausfold/.github` repo),
`homebrew-tap`, and the consumer config (`~/.config/nix`). Each keeps its
**own** rules — only the shape is shared. The differences worth knowing:

- **`org-profile` and `homebrew-tap` have no `.agents/setup.sh`.** Neither is a
  flake, so there is nothing to bootstrap; their `.agents/README.md` records
  that as a decision rather than leaving a gap-shaped silence. Every other repo
  carries the same script, adapted only in its opening comment.
- **`~/.config/nix` also carries a flow**, not just instructions:
  `.agents/skills/rebuild/SKILL.md`, symlinked into `.claude/skills/` and
  `.opencode/skills/` exactly as `ship` and `docs-sync` are here. Its
  `.claude/settings.local.json` stays put — a pre-approved tool-call allowlist
  is machine-local permission state, not a project rule.
- **haus ships this shape to users, too.** `haus.ai.skill` installs a
  `consumer-AGENTS.md` + `consumer-CLAUDE.md` starter pair rather than a lone
  `CLAUDE.md`, and `haus doctor` checks for the pair. It obeys the rule itself:
  the skill and `haus.ai.instructions` are written once per client the machine
  installs, each at the path that client reads. ⚠️ `haus.agents.*` has **no
  alias** (`haus/modules/moved.nix`), so writing it is an eval error.

Adding a new repo to the family? Copy the *pattern* from any of them, never the
text: `git mv CLAUDE.md AGENTS.md`, leave a `CLAUDE.md` holding `@AGENTS.md` plus
its client-only wiring table, move any `.claude/hooks/*` script to
`.agents/setup.sh`, and add the `GEMINI.md` symlink, `opencode.json` and real
`.github/copilot-instructions.md`.
