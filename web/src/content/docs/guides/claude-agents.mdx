If you drive [Claude Code](https://claude.com/claude-code) from a nebelhaus
machine, the rice hands you a small tool called **`holt`** — it makes running
several agents at once safe, and makes closing a pane something you never have
to think about. It works on **any git repo**, not just nebelhaus, and you get it
for free the moment the rice is on your `PATH`.

<Aside type="note" title="Where holt sits among the CLIs">
`holt` is one of the [rice's four CLIs](/start/the-family/#the-clis-at-a-glance),
and the only one that isn't *about* nebelhaus at all: it's
[its own product](https://github.com/nebelhaus/holt), a worktree-lifecycle
substrate the rice merely takes as a flake input and puts on your `PATH`. You
don't need to be a nebelhaus contributor — or a nebelhaus user — to use it.
</Aside>

## The problem it solves

Run two Claude agents in the same checkout and they fight: one switches the
branch out from under the other, uncommitted edits collide, and closing a pane
mid-thought can lose work. `holt` fixes both by giving **every agent its own
checkout**.

Press **`Super a` (⌘A)** in any repo's terminal tab and the rice spawns a fresh
Claude Code session in an **isolated git worktree**:

- its own checkout on a `worktree-<name>` branch, branched from the repo's local
  `HEAD`;
- living **outside** the repo, under `~/.cache/claude-worktrees/<repo>/<name>`,
  so your working tree stays clean and no build tool ever trips over it;
- so any number of agents can hack in parallel without ever touching each
  other's branch — or yours.

**`Super ⇧a` (⌘⇧A)** spawns exactly the same isolated agent, but **in place of
the focused pane** instead of splitting a new one beside it — for when the tab is
already as subdivided as you want it and the pane you're looking at has done its
job. The pane it replaces is only *suspended*, never killed: quit the agent and
your shell comes back, focused, scrollback intact.

`Ctrl Alt Shift a` is the resident variant: the one agent per tab that's allowed
to edit the checkout you're actually looking at.

Prefer the launcher? **Spawn Agent** in Pounce (`⌘Space`, type "spawn") does the
same thing from the GUI, for [whichever client you've made the
default](#spawn-from-pounce--and-choose-the-default-client): pick a repo, type
what you want done, and
it creates a worktree **named after the task** — not the random
`luminous-twirling-codd` an unattended agent would coin — and drops a session
into that repo's tab. Naming the branch from the prompt is the whole point; the
palette is just the shortest path to it.

<Aside type="tip" title="Closing a pane never loses work">
When you close a `Super a` pane, the rice doesn't just delete the checkout. Any
uncommitted edits are first parked as a `wip:` commit on the branch, then the
checkout is removed. **Only branches whose work has already merged get reaped** —
everything unmerged survives on its branch, and the agent transcript survives
too. The checkout dir is disposable; your work isn't.
</Aside>

## Resuming a session

Because the work lives on the branch (and the chat in your client’s transcript),
a closed pane is never a dead end. Run `holt` bare to see everything you can pick
back up, across **every** repo:

```sh
holt                  # list every parked / live agent worktree, all repos
```

```
🌫  agent worktrees you can resume (holt <name>, or <repo>/<name>)
  repo         name                       state  agent  last commit
  nebelung     sparkle                    parked claude 2 hours ago — wip: auto-saved on pane close
  pounce       quick-emoji                live   codex  10 min ago — add fuzzy weights
```

To pick one back up, name it — `holt` rebuilds the checkout and reopens the chat
in the same directory, so that worktree's client resumes with its full history:

```sh
holt sparkle          # rebuild the checkout + reopen the chat (that worktree's client)
holt nebelung/sparkle # qualify with the repo when a name exists in two repos
```

## Spawn from Pounce — and choose the default client

For a named worktree without first finding the right terminal tab, summon Pounce
and run **Spawn Agent**. Pick a repository, describe the task, and it creates a
`worktree-<task-name>` checkout before opening the configured client in that
repo's zellij tab.

Set the client declaratively:

```nix
nebelhaus.agents.default = "codex"; # or "claude" (default), or "opencode"
```

`holt` records that client with the worktree. Changing the option therefore only
changes **new** spawns: a parked Codex task still reopens through `codex resume`,
and an OpenCode task through `opencode --continue`.

The option drives the ⌘A keybinds and the `c` shell alias too. Only Claude Code
can make its own worktree (its native `--worktree` flag, which fires
`holt hook create`); for Codex and OpenCode, ⌘A runs **`holt new`** instead — the
same checkout, branch, registry entry and parent session, made from the outside.
Spawn Agent takes a third door, `holt spawn`, because the palette has no pane to
be a child of — same worktree, named after your prompt.

A separate option says which clients are **installed**:

```nix
nebelhaus.agents.clients = [ "claude" "opencode" ];   # the default
```

`agents.default` must be one of them, and the rebuild says so by name if it
isn't — which is the point: naming a client you didn't have used to fail at
spawn time, *inside the pane*, after the worktree already existed. Pounce's
Spawn Agent still checks `command -v` before it creates anything, for the case
the assertion can't cover (a hand-managed install that moved).

<Aside type="caution" title="Overlay, don't add">
Want a patched build of a client — a wrapper, a postInstall patch? **Overlay the
package** (`claude-code`, `codex`, `opencode`) rather than putting your own
derivation in `home.packages` beside it. Two derivations shipping the same
`bin/claude` collide in one profile, and the rebuild fails with
`two given paths contain a conflicting subpath`.
</Aside>

### Four Returns on the prompt step

The task field isn't just a box to type in — *how* you commit picks what happens
next:

| Key | Does |
|---|---|
| `↵` | Spawn on what you typed |
| `⇧↵` | Newline — the task is usually a list, not a sentence |
| `⌘↵` | Grab a screenshot first (`screencapture -i`), then spawn — cancel the capture and you're back in the box with your text intact |
| `⌥↵` | Your drafts — the box is kept on any dismissal, so a paragraph lost to a stray click into another app lands here |

The screenshot is saved under `~/.cache/nebelhaus-agent-screenshots/`: Codex
receives it as an initial image, Claude and OpenCode get its path in the first
prompt. This used to be a separate **Spawn Agent with Screenshot** command, but a
screenshot *row* is fuzzy-matched — a task merely containing the word
"screenshot" would steal Return — so it's an action-bar binding now, which can't
be matched. You write the task first and point at the thing second, which is the
better order anyway.

## Cross-repo work: `holt child`

Sometimes an agent working in one repo needs to change **another** one — say a
session in the workshop that has to touch a sub-repo. Don't reach for a raw
`git worktree add`: that skips the registry, so the statusline never learns to
track it and its PR goes invisible. Use `holt child` instead:

```sh
workshop_root="$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")"
cd "$(holt child "$workshop_root/nebelung")"
```

That creates a worktree of the *other* repo, **registers it as a child of your
current pane** (so its PR shows up in the statusline where you're working), and
prints only the new checkout path — hence the `cd "$(…)"`. Resolving the
workshop root through Git keeps the command independent of where you cloned it.

## Cleaning up

Most cleanup is automatic: closing a pane reaps a merged branch, and every `holt`
listing first self-heals by sweeping parked branches whose PR has since merged.
But some things end a pane *without* the graceful hook — a reboot, a crash, or a
`holt child` checkout (which the hook never owns, since the pane that made it
isn't the one it belongs to). For those, sweep on demand:

```sh
holt reap             # reap every LANDED worktree now — parked ones, plus
                      # clean & merged live checkouts no pane is open in
```

`holt reap` is deliberately conservative: it leaves anything **dirty**, anything
**unmerged**, and any checkout a **pane is still open in** — not only yours but
any other session's, because a just-merged branch looks exactly like a finished
one while its agent is still sitting in it. Only landed work that nobody is
standing in gets removed.

## When a session outran its PR: `holt reship`

You merge the PR, keep talking to the agent, and it makes a few more commits.
Those commits are now in an odd place: **the PR that covered them is closed, and
GitHub deleted the branch's remote counterpart when it merged** — so they're
committed, unpushed, and unreviewed, on a branch nothing is watching.

`holt` never reaps such a branch (a merged PR only counts as landed when the
branch tip is still the exact commit it merged), and it says so everywhere:

- the listing marks the row **`live+3`** — three commits past the merge — and
  prints a one-line legend under the table;
- `holt reap` names it instead of sweeping it: `⏏ kept sparkle (nebelhaus) —
  merged PR #12, 3 commit(s) since`;
- the statusline shows an **orange `3^`** where it used to show `⏏`.

One command clears it:

```sh
holt reship            # push this branch, open the follow-up PR
holt reship sparkle    # …or name one, from anywhere
```

It pushes the branch (re-creating the remote GitHub deleted) and opens a PR
against the default branch, with the commits since the merge listed in the body.
If a PR is already open for the branch, it just pushes to it.

## Setting work aside: `holt park`, never `git stash`

`git stash` looks like it belongs to the checkout you're standing in. It doesn't.
The stash stack lives in the repo's shared `.git` dir, so **every agent worktree
of a repo — and the main checkout — push and pop the same stack.** Two panes
stashing at once means either can pop the other's entry into a tree that never
asked for it, which is a confusing mess at best and lost edits at worst.

So park instead of stashing:

```sh
holt park "half-done refactor" # whole dirty tree → one wip: commit on THIS branch
holt unpark                    # rewind it — changes back, uncommitted
```

`holt park` commits everything — tracked edits, untracked files, deletions — as a
single `wip:` commit on the branch only this pane has checked out. It's the same
thing the pane-close hook does automatically, just on demand. Nothing is shared,
so no other agent can touch it; it survives a pane close; and `holt` lists it as
that worktree's last commit. `holt unpark` puts the changes back in the working
tree, uncommitted, exactly as they were.

<Aside type="caution" title="unpark won't rewrite what you've pushed">
If the `wip:` commit has already been pushed — it's visible in an open PR —
`holt unpark` refuses, because rewinding it locally turns a file restore into a
force-push. It prints the manual escape hatch (`git reset --mixed HEAD^`) and
leaves the commit alone. Parking on a branch that isn't a `worktree-*` one
(say, `main`) works, but warns: a `wip:` commit shouldn't drift onto a branch
you push.
</Aside>

## Which tab wants you

Run agents in eight tabs and the question is always the same one: which of them
is sitting on a permission prompt? The rice answers it in the tab bar itself — a
filled badge beside the name of any tab holding agent panes. The badge carries a
count — how many agents live in that tab — on a background coloured by what the
most urgent one is doing:

| Badge | Means |
|---|---|
| **peach** | an agent is blocked on you — a permission prompt, or it's asking a question |
| **sky** | an agent is mid-turn, working |
| **green** | the agent finished its turn; nothing is waiting |
| *(no badge)* | no agent panes in that tab |

The number is the exact count of agent panes in the tab; the colour is the most
urgent state among them, so peach always wins: the tab that needs you never hides
behind a tab that's merely busy. And it's *status*, not a notification — a green
badge stays green until that agent starts another turn or its pane goes away.
Looking at it doesn't dismiss it.

This is the same signal as the [`agents` bar pill](/guides/the-bar/), reported by
the client's own lifecycle hooks (which is why it's exact rather than guessed —
the agent says what it's doing, nothing scrapes the screen for it). The pill is
for when you're out in the GUI; the badge is for when you're already in the
terminal. It lights up as soon as an agent pane reports, and stays invisible if
you never run one.

Every client reports through one command, `agent-state <working|waiting|idle|
remove> <client>`, which the rice puts on your `PATH`:

| Client | Wiring | Who writes it |
|---|---|---|
| **OpenCode** | `~/.config/opencode/plugin/nebelhaus-agent-state.js` | the rice, for you |
| **Codex** | `UserPromptSubmit` / `PermissionRequest` / `Stop` in `~/.codex/hooks.json` | the rice, for you — Codex then asks you to **review and trust** those hooks the first time it starts, which the rice deliberately doesn't bypass |
| **Claude Code** | `UserPromptSubmit` / `Notification` / `Stop` / `SessionEnd` hooks in `~/.claude/settings.json` | you — these four are yours to wire, and the rice leaves them alone |

<Aside type="note" title="What the rice *does* write into `~/.claude/settings.json`">
Those four agent-state hooks are yours. The **worktree** hooks aren't: the rice
declares `WorktreeCreate` / `WorktreeRemove` (pointing at `holt hook create` /
`holt hook remove`) and re-asserts them on every rebuild, along with the
statusline, `permissions.defaultMode` and a few TUI keys. It merges into the
file rather than replacing it, and touches no other hook event.

That's deliberate. Claude Code rewrites its own `settings.json` on its own
schedule, and a hand-written hook it doesn't know about can go with it — you'd
find out at pane close, by losing a worktree's parking. Declared, the worst case
is one `haus rebuild` instead of silent data loss.
</Aside>

A pane's row also disappears on its own once the pane is gone, whether or not its
client said goodbye. That matters most for Codex, whose hooks have no
session-*end* event at all — but it's the same thing that clears the row of a
Claude agent you killed, or one that crashed.

## The statusline HUD

The rice points Claude Code's status bar at a small HUD driven off the worktree
registry, so you can see where every agent stands without leaving the pane.
**Row one is this session's own worktree** — its name, a status token, and its
GitHub PR pill. The **rows below are the worktrees this session spawned** (across
whatever repos they live in), each with its repo, name, token, and PR state. The
cross-repo GitHub lookups run detached and cached, so the bar never stalls your
prompt. Your own row doesn't wait on that cache to warm: Claude Code tracks the
current branch's open PR itself and hands it to the statusline, so a PR you just
opened gets its pill — with the real GitHub URL behind it — right away, while the
cache stays the source for the states Claude Code stops reporting (merged,
closed).

The token is one mutually-exclusive slot:

| Token | Means |
|---|---|
| `⏏` | branch is merged into `main` — closing the pane reaps the worktree |
| `N^` | `N` commits on the branch, not merged yet |
| `N^` *(orange)* | the PR merged and `N` commits landed **since** — no PR covers them, nothing is pushed. [`holt reship`](#when-a-session-outran-its-pr-holt-reship) |
| `+A -D` | uncommitted line changes, when nothing's committed yet |
| *(nothing)* | identical to `main` — no news is good news |

### The right-edge chips

Flush right on row one, a few small per-session chips: how far behind your pinned
nebelhaus is (`⇡N`, what `haus update` would pull), context used, session cost,
then the two that tell you what this pane is *actually running*.

**Permission mode.** Auto is the rice's default, so it's the silent one — same
"no news is good news" rule as the status token. Everything else is a positive
mark, told apart by how many chevrons it has rather than by colour alone:

| Chip | Mode |
|---|---|
| *(nothing)* | `auto` — the default you live in |
| `⏵` | `default` — gated, asks before every tool |
| `⏵⏵` | `acceptEdits` — edits sail through |
| `⏵⏵⏵` | `bypassPermissions` — no gates at all |
| `⏸` | `plan` |
| `⊘` | `dontAsk` — deny anything not already allowed |

**Model.** A short family + version tag — `O5`, `S5`, `H45`, `F5` — always
present, so you can tell at a glance which pane is on which model.

On **Fable** and **Mythos** the tag also isn't the only signal: the whole HUD
block picks up a dark amber background, painted edge to edge across every row
it draws. Two characters at the far right of one row is the wrong place to
answer "which of these panes is on the expensive model", and that's the question
you actually ask when you're looking at a screen full of them. The tag stays —
the tint is a second reading of the same fact, so a terminal that drops
backgrounds loses nothing. It's drawn per pane, so a mixed fleet genuinely shows
a mixed set of panes.

These two work together. Switching to a model that has no auto mode drops you to
`default` without announcing it; the `⏵` tells you the mode changed and the model
chip tells you why.

:::note
On stock Claude Code the mode chip updates at **turn boundaries**, not while you
cycle `shift+tab`. Claude Code re-runs the statusline on every flip, but it
doesn't put the mode in what it hands the statusline — it only *records* the mode
when a turn is submitted, and there's no hook for it either. So the chip means
"the mode as of your last submitted turn": good at catching a mode that changed
*under* you, and still while you cycle modes idle.

The gap is one field wide, and it can be closed downstream: the statusline
prefers a `permission_mode` key in its stdin payload and only falls back to the
transcript when it's missing. Claude Code's own payload builder already receives
the live mode, so a build that emits it — the author's host patches the binary to
do exactly that — gets a chip that tracks `shift+tab` as you press it, no turn
needed.
:::

## Links — every URL a pane's session saw

The same statusline pass that drives the HUD also notes which Claude transcript
each pane is running, and Pounce turns that into a command. Press **⌘L** in the
terminal (or summon the palette with **⌘Space** and run **Links**) to get every URL
from the focused pane's whole Claude Code session — newest first, including links
buried in collapsed tool output or that scrolled away hours ago. **⏎** opens the pick
in your browser.

GitHub PR and issue links come back enriched with their real title and
open/closed/merged state — a parallel, cached `gh` fetch capped at ~2s, so a slow
network degrades to plain links rather than a hung palette. A pane not running
Claude Code falls back to its visible scrollback.

## Command summary

| Command | What it does |
|---|---|
| `holt` | List every parked/live agent worktree across all repos (self-heals first) |
| `holt <name>` | Resume one: rebuild its checkout and reopen its recorded agent chat |
| `holt resume <name>` | The same thing, spelled out |
| `holt reap` | Sweep every landed worktree now (keeps dirty/unmerged/any open pane) |
| `holt child <repo>` | Make a worktree of another repo as a child of this pane (cross-repo) |
| `holt park [label]` | Set the dirty tree aside as a `wip:` commit on this branch (use instead of `git stash`) |
| `holt unpark` | Undo the last `wip:` commit — changes back in the working tree, uncommitted |
| `holt reship [name]` | The PR merged and the branch kept committing: push it and open the follow-up PR |
| `holt new [name]` | Make a worktree of **this** repo and open the default client in it — what `Super a` runs when that client isn't Claude Code |
| `holt agent default` | Print the configured spawn client |
| `holt spawn <repo> <name>` | A named worktree for a spawner with no pane of its own — what Pounce's Spawn Agent calls |
| `holt hook create` / `holt hook remove` | The hooks Claude Code's `--worktree` fires — you don't call these by hand |

Add `--json` to the listing for a machine-readable version, `--version` for
holt's own.

<Aside type="note" title="Related shell touches">
New panes born inside a worktree hop back to the repo's **main checkout** by
default (`Super P`), so a shell lands somewhere stable; `Super ⇧P` is the no-hop
escape hatch that keeps you *inside* the worktree. See
[The shell](/guides/the-shell/#zellij-keybindings) for the full set.
</Aside>
